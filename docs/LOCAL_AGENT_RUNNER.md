# Local LLM Patch Runner

`scripts/agent_runner.ps1` is a project-local v0 runner for bounded local-agent work. It is intentionally a constrained patch executor, not a free-roaming autonomous agent.

## Architecture

The runner owns authority over the repository:

- Git branch creation and resume behavior.
- Task and config loading.
- LM Studio API calls.
- Patch parsing and safety checks.
- Patch application.
- Validation.
- Repair attempts.
- Rollback.
- Explicit staging and commits.
- Run reports.

The model only produces:

- A plan.
- Unified diff patches.
- Repair patches.
- Optional summaries inside reports generated by the runner.

The model never runs shell commands, chooses branches, writes arbitrary files, validates the project, stages changes, commits, merges, or pushes.

## Why Unified Diffs

Unified diffs are inspectable and can be checked with `git apply --check --whitespace=error` before any file is changed. v0 rejects noisy patch output instead of trying to extract a patch from Markdown, code fences, explanations, or tool-call text.

This is stricter than Continue, OpenHands, or Aider style workflows. Those tools can be useful, but this project needs a runner that treats the model as an unreliable patch generator and keeps all operational authority in local deterministic code.

## LM Studio Setup

Start LM Studio, load the local model, and enable the local server. The expected default endpoint is:

```text
http://localhost:1234/v1
```

Verify the server and model from PowerShell:

```powershell
Invoke-RestMethod -Uri "http://localhost:1234/v1/models"
```

The default model in `scripts/agent_runner.config.json` is:

```text
qwen2.5-coder-7b-instruct
```

## Run The Proof Task

Recommended first run:

```powershell
.\scripts\agent_runner.ps1 -Task .\tasks\agent-runner-proof-task.md -NoCommit
```

If the dry run is clean, restore or commit as appropriate, then run without `-NoCommit`:

```powershell
.\scripts\agent_runner.ps1 -Task .\tasks\agent-runner-proof-task.md
```

The runner starts from `develop`, creates the branch named in the task file, writes artifacts under `docs/agent-runs/<timestamp>/`, validates, and commits only after validation passes.

## Safe Defaults

For this machine, use:

- One task at a time for first runs.
- `MaxFilesChanged`: 2 to 4.
- `MaxLinesAdded`: 250 to 400.
- `MaxAttempts`: 3.
- Temperature `0`.
- `top_p` `1`.
- Non-streaming API calls.

After several clean proof runs, overnight work may use:

- 2 to 3 tasks maximum.
- 4 to 6 files per task.
- Up to 3 repair attempts.

Do not run open-ended sessions.

## Troubleshooting

Dirty git state:

- Commit, stash, or remove unrelated local changes before starting.
- Use `-Resume` only for an existing runner branch with only runner-owned artifacts or approved task changes.

Branch exists:

- The runner refuses existing branches unless `-Resume` is passed.

LM Studio not running:

- Start the LM Studio local server and check `/v1/models`.

Model missing:

- Load or download the configured model, or pass `-Model <name>`.

Invalid patch:

- v0 rejects Markdown, code fences, absolute paths, `../` traversal, blocked paths, binary patches, disallowed deletes, disallowed renames, and budget overruns.
- If `git apply --check` reports a corrupt patch, inspect the saved sanitized `patch-attempt-*.diff`. Common causes are malformed hunk headers such as `@@ -0,0 +1 @@`, hunk line counts that do not match the actual added/removed/context lines, or inconsistent `a/` and `b/` paths. Repair attempts include the rejected sanitized patch, the exact apply-check error, and a targeted diagnostic for shorthand hunk headers when detected.

Validation failure:

- The runner asks for repair patches up to `MaxAttempts`.
- If attempts are exhausted, failed changes are rolled back unless `-KeepFailedChanges` is set.

PowerShell path quoting:

- Run from the repository root.
- Keep paths with spaces quoted when passing parameters.

CRLF/LF patch issues:

- The runner uses `git apply --check --whitespace=error`.
- If a local model repeatedly emits whitespace-damaged patches, lower the task size and try again.
